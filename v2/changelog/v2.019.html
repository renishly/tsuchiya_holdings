v2.019: known outages are low warnings that count the days

13 Nov 2026Addendum A56

When a source site says it is down for maintenance, the error report now shows it once as a low item that says how long its data has been missing. It no longer raises a medium error every run, and the dashboard no longer shows Main as Needs attention because of it.

What counts as a known outage

  • A site answers 429 or 5xx and says why: a Retry-After header or a maintenance page (メンテナンス). A bare 5xx with no reason is still an unknown failure (medium).
  • The first case: www.grandy.co.jp has served a maintenance notice (a precaution against a published software vulnerability) since 1 Nov 2026.

What you see

  • One low item in its area, e.g. Peers: www.grandy.co.jp: known outage (503, maintenance page, Retry-After 3600), failing since 2026-11-01 (12 days); newest data is from 2026-10-22 (22 days old). The counts go up each run.
  • The Run status step stays ok, and its note shows the item, so you can see something is up without the agent being flagged.
  • The agent keeps trying the site each run. The first successful fetch ends the outage, and for 3 days the report shows an info item: back after N days.
